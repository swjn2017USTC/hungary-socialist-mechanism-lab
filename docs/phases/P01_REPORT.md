# P01 Report — Runnable Toy-4 Vertical Slice

Date: 2026-10-07 · Plan: `P01_TOY4_PLAN.md` · Baseline: `1f5b233f452468701ca2d87b3ec032be4654b070ed24e5853232c997d7d61b6f` (unchanged, verified)

## What was built

A real F0 multi-commodity economic simulator (1957Q1–1985Q4, 116 ticks, 20 contract regions, 4 commodities, 1,600 default households, 40 representative productive organizations) with strict per-cell accounting, checkpoints, deterministic replay digests, compact Parquet/DuckDB output, and a same-path benchmark. Toy economic magnitudes are synthetic engineering fixtures, not historical fits.

New modules:

| Module | Content |
|---|---|
| `contract/schemas.py` | `TOY4_COMMODITY_IDS`, `Toy4Parameters`, `Toy4InitialRecipe`, `ScenarioSpec.kind="toy4"` with full run-gate validation |
| `engine/state.py` | `Toy4State`/`Toy4Forcing`/`TickFlows`/`Toy4History`, `initialize_toy4`, `tick_toy4`, `produce_leontief` |
| `engine/accounting.py` | `check_toy4_invariants`, per-cell material/cash ledgers, `AccountingError` |
| `engine/toy4.py` | `load_toy4_forcing`, `canonical_toy4_bytes`, digest chain, `run_toy4` lifecycle |
| `engine/rng.py` | `snapshot`/`from_snapshot` (PCG64 state + counted draws) |
| `storage/checkpoint.py` | `toy4-checkpoint-v1` atomic save + strict resume gates |
| `storage/toy4_output.py` | five compact tables (aggregates / national_accounts / household_budgets / tick_diagnostics / events) |
| `benchmarks/harness.py` | `benchmark toy4`: 7 cases, real economic loop |

Data/fixture surface: `data/fixtures/p01_toy4_{import_supply,export_orders}.parquet` (464 rows each: 116 quarters × 4 commodities, `toy4_commodity_unit`, national rows) declared in `data/manifests/{sources,variables,artifacts}.yml` as `synthetic_fixture` exogenous forcing; `.gitignore` carries exactly two un-ignore rules for these files. Energy imports are 150/quarter except 1973Q4–1974Q3 (0) — a declared deterministic perturbation, not an oil-shock reconstruction. Export orders are 20 capital_goods/quarter.

Commodity axis is the last array axis throughout the kernel; no scalar-goods shortcut exists (`FORBIDDEN_COMMODITY_IDS` still rejects `goods`). Extending to 8/16 commodities later requires widening the declared vectors and `TOY4_COMMODITY_IDS` in the schemas (the validators currently pin the four Toy-4 ids); the kernel loops and ledgers themselves are commodity-generic.

## Acceptance criteria (plan §J)

1. **Full horizon**: default, N1000 and N2000 all complete 116 ticks 1957Q1→1985Q4 over the 20 contract region IDs with exactly 4 commodities and 40 producing organizations; no goods aggregate anywhere in the runtime. ✔
2. **Observable quantities**: desired/ordered/allocated/delivered/available/used/realized/unmet plus per-commodity inventories in every tick's compact rows; no probe renaming, no same-tick double use (regression-tested), no cross-commodity pseudo-conservation (each commodity accounted separately). ✔
3. **Household mechanism**: budget and regional availability bind simultaneously; shortage and forced saving are realized-value differences; weighted demand/purchase/inventory/cash are mutually consistent; capital goods never retailed to households. ✔
4. **Accounting**: all 116 quarters pass local + global material and household cash ledgers per cell (atol 1e-9, rtol 1e-10); violations fail closed (regression-tested per ledger); residuals and tolerance ratios are stored per row and independently recomputable — SQL recomputation max ratio ≤ 1. ✔
5. **Replay equivalence**: two independent same-seed runs and a tick-40 resume agree on final state, compact trajectory, digest and RNG; boundary-1/115 equivalence and corrupt/no-op checkpoint refusals are regression tests; the implementation restores the RNG snapshot (never re-draws prefix from seed). ✔
6. **Forcing integrity**: deterministic, admitted through the P00 registry (role/rights/digest/unit/period), full 116×4 grid enforced, hash-reproducible; only external fixtures enter; initialization is grade-S structural assumption, explicitly not a historical parameter/population claim. The loader pins the declared coverage to the contract core window and binds each artifact ID to its exact variable, so self-consistent but shortened/shifted/swapped fixtures are refused. ✔
7. **CLI & storage**: run/paused/resume/summary behave with correct exit codes and lifecycle; `summary` recomputes `summary.json` bytes against `manifest.output_hashes` before reading back, so economic-field tampering is refused; DuckDB and Parquet are content-equal; parameters.json/initial_recipe.json/manifest/checkpoint provenance auditable; compact output stores no micro trajectory. ✔
8. **Benchmark**: all seven cases execute the real economic loop and pass performance/accounting/resource gates; evidence is economic-loop throughput, not the P00 probe; toy4 reports carry only workload-appropriate notes. ✔
9. **P00 preservation**: role/frequency/rights/target/reserved-window/failed-run guards and the smoke path unchanged (all 132 pre-existing behaviors still pass); BASELINE bytes and pinned hash unchanged; no historical fitting, 16 commodities, NEM/LLM/ABC/Sobol or complex SocioVerse code added. ✔
