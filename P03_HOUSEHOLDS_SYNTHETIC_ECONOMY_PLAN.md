# P03 — Households / Social Contract / Durables / Second Economy

## Context
实现 P03：将 county-conditioned、加权 synthetic households 接到现有物质经济、现金账本和季度重放路径，覆盖 A–L 全部要求。家庭是代表性合成 cohort，不是真实户清册；历史聚合锚点约束人口/消费/stock，未观测联合分布与行为参数明确标为结构假设。禁止 household LLM、通用 decision agent、scalar legitimacy，以及 grievance→protest 捷径。

## 已核实的基础与执行边界
- 依据 `BASELINE.md` §5–7、§9.7–9.12、§10、§18.2、§20–24、§26–30，以及 `OMP_PLAN.md` §7。P03 必须证明四个 household fixture 和 1k/5k/20k scaling；未审计的 featured goods/waiting 数据允许用 synthetic fixture，但不能声称历史校准。
- `docs/phases/P02_REPORT.md` 报告 5,000 households / 200 organizations / 116 ticks 的闭合 material/finance ledger、private plot、checkpoint/replay、compact output。报告同时明确默认物质链退化，数值初始化搜索未解决；当前源码未见可撤销此结论的 steady-state 实现。不要重新运行来“确认”已报告的失败，不改运输/稳态机制来让 P03 看似成功。P03 可完成机制实现和独立 fixture 验证；集成轨迹保留该已知限制，不作历史拟合或 M1/M4 因果结论。
- 当前 household 只有 id/region/weight/size/cash/deferred_receipt/wage_claim；当季 basket 是 `(N,G)`；durable/dwelling 是区域 stock。`_households` 均匀 county、`desired_per_person` 固定篮子、`_person_shares` 全国 size 比例工资分配是本次 clean cutover 的旧路径。
- 可复用：`StrictModel`、`DataRegistry` admission/loaders、单次 `build_material_initial_conditions`、`RngRegistry`、`produce_leontief`、`np.bincount`/segmented allocation、成对 journal、stock-cell catalog、共享 checkpoint field-spec、canonical digest、streaming Parquet 和 DuckDB views。没有现成 household demand/substitution/time-use/expectation kernel，新增以下数值模块，不建立第二个 scheduler/runtime。
- LSP status 已核实：项目没有 language server。变更前用工具 grep 盘点下文指定符号；所有调用迁移，无旧参数兼容别名。BASELINE 字节和 research-contract hash 不变，核心窗口仍为 1957Q1–1985Q4。

## Approach — 执行顺序与共同契约
按 A/J → B → C/D → E/F → G → H/I → persistence/output → K/L 顺序提交可运行增量。A/J 的 schema、typed arrays、serializer、scenario 必须同批接入，避免 field-spec drift；随后各行为先用 tiny kernel fixture 证明再接入 `tick_material`。需求与第二经济的供给/支付均在现有季度引擎中执行，不能独立跑一套家庭经济。

### B. County-conditioned synthetic population generator
1. 新建 `src/hsm_lab/engine/households.py`：`build_synthetic_households(spec: ScenarioSpec, rng: RngRegistry) -> HouseholdInitial`，替换 `engine/initial.py::_households` 与 `_plot_cohort`/material 里重建 cohort 的逻辑。生成器只在初始化调用一次；actual region 顺序复用 contract 的 19 counties + Budapest，id 0..N−1。拓扑/企业 organization ID 规则保持。
2. `HouseholdInitialRecipe` 保存 `role="initial_state", grade="S", evidence_status="structural_assumption", observation_at=None, population_kind="synthetic", counties:list[CountyHouseholdSpec]`。每 county 明确 `household_total, persons_total, urban_share, size_probabilities[6], occupation_shares[4], education_shares[3], child_share, elderly_share, plot_share, second_share, informal_access, western_exposure, tenure_shares[3], durable_ownership[4]`。JSON 中写出 20 行，不在 runtime 使用均匀 region fallback。
3. 默认纯工程 recipe：令 county ordinal `r=0..19`、scale `a_r=1+r/40`，`household_total_r=5000*a_r/Σa`；`urban_share_r=.35+.30*r/19`（不是匈牙利城乡事实）；size probabilities `[.10,.20,.25,.20,.15,.10]`，mean size=3.4，persons=`3.4*household_total`；occupation shares `[.35,.25,.25,.15]`、education `[.60,.30,.10]`、children share=.20、elderly=.15；plot share=`.30*(1-urban_share)`，second share=.20，informal_access=.5，western_exposure=0，tenure `[.4,.2,.4]`，initial durable `[.05,.03,.10,.005]`。county差异是有意构造的 S fixture，不能映射成“Budapest 实测”或历史排序。
4. county内枚举size1..6×urban/rural×occupation4，共960最大cells；masses是marginal的maximum-entropy product。`mean=persons_total/household_total`必须≥1；mean=1直接size1 pointmass，mean=6直接size6 pointmass。其它mean用`p_s∝base_p_s exp(λs)`稳定log-softmax、二分λ至mean误差≤1e-10（最多128次），不能clip anchor。mean>6时支持扩为`1..ceil(mean)+2`，新增tail base mass=`base_p6*2^(-(s-6))`后normalize再tilt；solver不收敛或margin矛盾则拒绝。urban/occupation零share删除零质量cell，N coverage gate按实际positive cells计算。
5. 每正质量 cell 至少一条代表 household；剩余 `N−positive_cells` 用 Hamilton largest-remainder 按 cell mass 分配，tie=(region,size,urban,occupation)，每条 weight=`cell_mass/cell_count`。因此改变 N 不改变 `Σw`、`Σw size` 或核心 weighted county margins。若 N 小于正 cell数，formal run fail closed，报 `household sample cannot cover positive county strata`；tiny unit fixture直接传数组不走 formal N gate。当前默认960 cells 支持 1k/5k/20k。
6. age composition固定算法：children=`min(size−1,floor(size*child_share+.5))`，elderly=`min(size−1−children,floor(size*elderly_share+.5))`，adults=`size−children−elderly`，working_adults=adults；education、tenure、plot/second参加用county-cell内categorical CDF。stochastic时只从 `rng.uniform("household.initial_attributes", N*5)` 一次取得教育、tenure、plot、second、access扰动；非stochastic各cell内第j条的5个quantile都取`(j+.5)/cell_count`，不调用RNG。保留exact household/people/urban/occupation totals；年龄/教育/参加分布是抽样近似，输出achieved margins。`pay_weight=working_adults*[1,1.15,1.30][education]`，access扰动=`clip(recipe_access+.2*(u-.5),0,1)`。sector由occupation映射 `industry/agriculture/services/administration` 的4个编译ordinal，不借用企业technology ordinal。
7. `HouseholdInitial` 扩展对应 static arrays；保存 row weights 与 achieved margins/hash。`build_material_initial_conditions` 使用实际加权 persons初始化组织劳动/plot土地；人口不会随 sample N 增大。工资 `_person_shares` clean rename为 `_household_pay_shares`，公式 `pay_weight/Σw pay_weight`，accrual、通常工资、late bailout payment 共用；全国池是既有 F1 工程近似，不假装已识别真实雇主。总 pay_weight=0 且工资due>0直接 AccountingError，不凭空创建受款家庭。

### C. Demand system 与季度冻结
1. 在新 `engine/households.py` 定义 `form_household_demand(state: MaterialState, parameters: HouseholdParameters, catalog: HouseholdCatalog) -> np.ndarray`，返回 float64 `[N,H]`；`tick_material` 开始冻结 household references、expectations、effort 与 income proxy，然后调用一次。另定义 `form_initial_household_demand(initial: HouseholdInitial, parameters: HouseholdParameters, catalog: HouseholdCatalog, nominal_wage_pool: float) -> np.ndarray`，用B静态数组、I初始状态与 `nominal_wage_pool=material_wage_rate*equivalent_persons` 创建initial numeric inputs，与runtime共用纯array计算kernel，不构造完整MaterialState或递归调initialize。`engine/initial.py::_quarterly_flow_value` 改用此initial basket映射到G的加权价值，不能保留旧dpp。retail replenishment 的 `region_persons*dpp` 改为 `Σw desired_h @ to_material`；household D block仍region×parent G，不扩成N条route。
2. household equivalence `e=adults+.7*children+.9*elderly`。income ratio `z=max(log(max(last_income,eps)/reference_income),0)`；reference_income 初始化为名义全国工资池×pay share（必须>0），之后固定作尺度，last_income只取已实现 cash income，不含借贷、自用或账面 wage claim。初始化last_income=reference_income、last shortage=0、last price index=1、wait/streak/backlog=0、reserved hours=0。peer消费用上一季 county weighted per-equivalent-person realized basket；western_exposure 使用 static S input，不伪造年度西方接触轨迹。
3. 默认 nondurable desired：energy=`.4e`，basic=`1.5e`，higher=`.25e*(1+.5z+.25*expectation_real_consumption)`，light=`e*(1+.25z+.10*peer_uplift+.05*western_exposure)`，personal=`.2e*(1+.25z)`，repair由E状态决定，construction由F的private desire决定。higher/light/personal再乘该户occupation与education multiplier；protected minimum不乘它们。`peer_uplift=max(peer_light/initial_peer_light−1,0)`，initial peer0时该项0。初始期待消费分量取I的S initial_entitlement；不从观测年度重置。energy城乡factor urban=.9/rural=1.1；这些S系数不主张个体医学/偏好事实。
4. 自用 opening plot food先抵 basic goal（不足才仍需购买），再抵 high goal（受同样 conversion及plot high quota，默认 plot全basic）。`B_income=max(wages+formal_plot_receipts+opening_deferred−plot_input_funding−second_input_funding,0)`；可释放旧存款 `draw=min(max(cash_open−opening_deferred,0), savings_draw_fraction*desired_durable_value)`，默认fraction=.25。`budget=min(pre_purchase_cash, B_income+draw)`；旧 deferred 已含 opening cash，不再计一次 income/cash；late direct receipts 和 late bailout工资到本轮结束才入账，不再买一轮。
5. 先只用income预算按最低 basket `basic_min=1.5e`、energy_min=`.2e` 分配预算；不足按这两个minimum的费用同比缩放。用剩余income按其它desired费用同比缩放（包含durable、basic超出minimum的部分）；最后把durable-only draw按尚未affordable的durable费用同比追加，超出目标的draw不释放，重算实际 `savings_draw` 与budget。购durable的draw不得挪去替代repair或一般消费；income预算可买所有H。各次acquisition消费时先扣匹配good的income份额、durable再扣draw，goods缺货留下对应planned资金，替代只能动该source的income份额。保存原desired、self-use调整后desired、availability-neutral affordable goals与planned spending；预算裁剪不是forced substitution。
6. 正式 acquisition 按 county×H weighted demand配给；调用现有 group-factor/retail handling 逻辑，但同 parent 多渠道共享一个 stock/handling上限并按 C5 priority依次消耗，不能各 H 重复获得整份 G availability。写 formal_h 后只投影一次到 G、retail edge flows、seller receipts。plot/second/source信息在 H 层保留，material acquisition `household_realized[N,G]` 包括所有实际来源，不含虚拟替代信用或 durable service yield。
7. `HouseholdParameters` 默认 `eps=1e-12` 仅用于无量纲比值/utility；不能用它吞掉 accounting error。空county demand、缺 route、空 stock→realized0与availability unmet；非法 price、未知 H→G、raw food acquisition、非finite参数/数组、negative预算直接配置/会计错误，不补全国池。

### D. Forced substitution、queue/search、postponement、saving
1. 新建 `src/hsm_lab/engine/household_allocation.py`：`allocate_household_baskets(state: MaterialState, flows: MaterialTickFlows, parameters: HouseholdParameters, network: MaterialNetwork, opening: MaterialStockSnapshot) -> None`，取代 material `_household_step` 的需求/配给部分；资金journal操作继续复用 `engine/finance.py` 与现有成对legs。固定执行顺序：plot self-use→formal exact goods→plot直接food补缺→second exact goods→forced substitution→余额/等待计量。每步用同一 remaining income/durable-draw budget、remaining physical source inventory，金额不循环。
2. 唯一替代 pair `Q=("higher_value_food->basic_food","refrigerator->repair_services","washing_machine->repair_services","television->repair_services","passenger_car->repair_services")`；前者每缺1 high购买2 basic，source-goal utility credit=.6、质量损失=.4；四类 durable临时以1 repair替代1 desired unit，temporary service credit=.25、loss=.75，不能获得 durable ownership或清空 durable backlog。只允许 affordability-neutral目标已获预算且发生 availability缺口时替代；无 availability缺口不能抢购替代品。durable repair替代先保障已有损坏stock维修，剩余才满足临时缺口。禁止 food→energy、durable→housing 或反向自动 quality升级。
3. source priority=Q顺序；每pair向目标channel剩余stock询价，量=`min(source_unmet*ratio, remaining_source_income_budget/target_price)`，county加权配给，再扣source unmet/资金/目标库存。仅一遍有限pairs，无recursive substitution。`household_substitution[N,Q]` 存source-unit替代量；physical realized_h存买到target units；goal_credit_h=`min(original_goal,exact_goal_fulfilment)+Σ(source substitution*credit)`，替代目标的额外实物不得再充作其原始goal credit。目标自身购买与替代额外购买分别记；虚拟credit不进material ledger，原goods availability unmet与substitution relieved quantities分列。
4. queue/search只针对 budget-affordable但未满足的商品；以正式第一次配给短缺率 `s_h` 计算 `queue_requested=.5*Σ(to_material-equivalent affordable unmet)` 小时，`search_requested=2*Σ(channel_shortage_rate)*informal_access` 小时。没有购买意图、纯预算不足→queue/search0。按 G 节剩余时间同比截断，实际小时计福利成本；search提高下一季 informal access最多 `.05*min(search_hours/10,1)`，不本季自动产生库存、不把其它county的物量免费搬来。此阶段 F1 不新增跨county shopping route。
5. 非耐用未满足需求不累成无限backlog，保存当期食品/质量缺口；durable/housing backlog跨季，并分别记录 budget postponement和availability postponement、waiting quarters。计算 `postponement_cost=.02*Σ(durable_backlog*(1+wait))+ .02*housing_gap*(1+housing_wait)`，是模型utility成本，不是现金支付。
6. 令 `planned_spending` 为同budget、同自用抵扣、忽略availability时的 affordable目标费用；所有实际cash purchase（含替代）不得超过它，剩余资金不能任意重投无目标商品。`forced_saving=planned_spending−actual_spending`；`voluntary_saving=budget−planned_spending`；两者非负且相加=`budget−spending`。旧未释放余额另记 `unreleased_savings=max(pre_purchase_cash−budget,0)`，late receipts另列，不能将全部cash增量叫forced saving。自用不是收入/spending；储蓄支出释放不制造income。

### E. Durable diffusion / ownership / replacement / waiting
1. 新建 `src/hsm_lab/engine/household_stocks.py`：`update_durable_stocks(state: MaterialState, flows: MaterialTickFlows, parameters: HouseholdParameters) -> None`。每种 stock属于合成代表cohort，允许fractional ownership `[0,1]`；输出 weighted diffusion rate，不声称离散真实购买年表。初始量来自 recipe；不复制成区域权威stock。
2. 默认 quarterly retirement hazard `[.005,.005,.004,.003]`；新增动态 `household_durable_repair_credit:float64[N,D]`（initial0）。当前retirement先算`raw_retired=opening_owned*hazard`，再用上季maintenance credit避免`min(raw_retired,.5*opening_repair_credit)`，effective retired为差额；old repair credit当季用后失效。本季实际maintenance services形成closing repair credit=`min(closing_owned,maintenance_acquired)`，只保护下季，不回改已退休/已购买上限；临时替代repair不进入此credit。stock next=`open−effective_retired+acquired`，购买request cap在配给前已知为`1−surviving_owned`；年龄用剩余old age+1与new age0的weighted mean、stock0时age0。`durable_repaired`记录maintenance acquisition，avoidance另外输出；不把维修信用当stock购入。
3. aspiration `target=clip(base+[.10*z+.20*peer_ownership+.10*expectation_real_consumption],0,1)`，base=`[.25,.20,.50,.10]`；新增扩散意向=`min(.02,max(target−opening_owned−old_backlog,0))`，新增replacement意向=effective_retired（不再把同一retirement放入扩散缺口）。`request_backlog=min(1−surviving_owned,old_backlog+new_diffusion_intention+replacement)`，desired购买=request_backlog；closing backlog=request_backlog−actual_acquired。预算不足与缺货均延期，不能每季追加全额desired。
4. durable正式配给county/type内按eligible affordable request×`(1+.1*waiting_quarters)`，共用 `allocate_capped_by_region(request: np.ndarray, priority: np.ndarray, weight: np.ndarray, region: np.ndarray, capacity: np.ndarray) -> np.ndarray`；同utility用于housing各tier。解`Σ_r w*min(request,λ*request*priority)=min(capacity,Σ_r w request)`，每county bracket λ∈[0,1/min_positive_priority]固定64次vectorized bisection；zero request/priority不分配、无容量返回0。实际HH获得值反算source扣减，不用nominal capacity造尾差，沿用accounting tolerance。wait对仍有backlog者+1、清空才0；替代repair不清购买backlog。本季购买stock服务下季生效。
5. maintenance repair demand=`Σ(surviving_owned*hazard)` 投到repair H，用于下季维护，replacement由当季effective retirement形成。同service的maintenance acquisition和D的temporary substitution分别归属，不能重复扣；当季maintenance只存next repair credit，不回改已形成retirement。durable ownership、等待、replacement、retirement、maintenance、avoidance与service yield分别输出。
